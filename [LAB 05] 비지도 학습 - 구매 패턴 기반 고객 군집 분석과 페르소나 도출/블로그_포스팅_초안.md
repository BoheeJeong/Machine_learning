# UCI Wholesale 고객 데이터로 보는 고객 세분화 & 채널 예측 대시보드

---

## 분석의 시작점

**"데이터로 읽는 유통의 미래: 직관을 넘어 예측의 시대로"**

과거 도매 유통업은 베테랑 영업사원의 '감'과 '경험'이 지배하는 영역이었습니다.

하지만 시장의 변동성이 극심해진 오늘날, 단순한 직관은 데이터가 보내는 정교한 신호를 이기지 못합니다.

실제로 **McKinsey & Company**는 데이터 기반 의사결정을 내리는 기업이 그렇지 않은 기업보다 **고객 유치 확률은 23배, 수익성은 19배** 더 높다고 강조한 바 있습니다.

**Bain & Company**의 2025 소비자 제품 보고서에 따르면, 글로벌 소비재(CPG) 판매 성장률은 2022년 9.8%에서 2024년 7.5%로 둔화되었습니다.

이는 과거와 같은 단순 가격 인상 전략이 한계에 도달했음을 시사하며, 데이터를 통한 정밀한 고객 이해와 운영 효율화가 지속 가능한 성장의 열쇠임을 보여줍니다.

글로벌 유통 공룡들은 이미 기존의 데이터를 활용하여 고객의 미래 행동을 예측하는 단계에 진입했습니다.

- **Sysco(시스코)**: 북미 최대 식자재 유통 기업 시스코는 AI와 디지털 영업 도구를 활용해 고객의 과거 구매 패턴을 분석, '구매 시점이 도래한 품목'을 선제적으로 제안하며 외식 수요 감소 위기를 정면 돌파하고 있습니다.
- **Amazon(아마존)**: 고객이 주문하기도 전에 물품을 인근 물류센터로 이동시키는 '예측 배송(Anticipatory Shipping)' 시스템을 통해 물류 패러다임을 완전히 바꿨습니다.

본 프로젝트는 도매 유통 산업의 비즈니스 로직을 **UCI Wholesale Customer** 데이터셋을 통해 구현하기 위해 기획되었습니다.  
데이터 전처리부터 모델의 판단 근거를 설명하는 **SHAP** 분석, 그리고 **태블로**를 통한 시각화 과정을 공유합니다.

## 1. 프로젝트 개요

본 프로젝트의 목적은 **UCI Wholesale Customer** 데이터셋을 활용하여 다음 세 가지 질문에 답하는 것입니다.

- **고객 세분화**: 고객은 어떤 구매 특성을 가진 그룹으로 나뉘는가? (K-Means)
- **채널 예측**: 신규 고객의 구매 패턴만으로 이들이 '호텔/레스토랑/카페 유형(Horeca)'인지 '소매 유형(Retail)'인지 판별할 수 있는가?
- **비즈니스 구현**: 현업 담당자가 실시간으로 예측치를 확인할 수 있는 환경을 어떻게 구축할 것인가? (TabPy & Tableau)

- **이상치(Outliers) 판별**: |z| > 3 기준을 적용했을 때 모든 품목에서 극단치가 존재함을 확인했습니다. 이를 방치할 경우 머신러닝 모델이 일반 고객이 아닌 **특이 케이스(VVIP 등)에만 과적합(Overfitting)**될 위험이 있습니다.
- **왜도 개선 확인**: 원본 데이터의 높은 왜도를 확인한 후, **로그 변환 권장 지수(log_recommended)**가 모든 품목에서 True임을 도출했습니다.

### 2. 데이터 탐색 및 전처리 | 전처리

**[요약]** 머신러닝 모델의 왜곡을 방지하기 위해 **Log Transformation**을 수행하고, 변수 간 단위 차이를 맞추기 위해 **StandardScaler**를 적용했습니다.

#### 2-4 Log Transformation (로그 변환)

- **Action**: 억 단위와 백만 단위 구매액 사이의 거대한 간극을 **로그 스케일**로 압축했습니다.
- **Value**: 우측으로 길게 늘어진 꼬리 분포를 정규분포 형태로 변환함으로써, 모델이 **모든 구매 구간의 패턴을 고르게 학습**할 수 있는 환경을 조성했습니다.

[그림: 로그 변환 후 히스토그램·박스 플롯]

#### 2-5 StandardScaler 적용

- **Action**: 서로 다른 품목별 구매 단위(Unit)를 **평균 0, 표준편차 1**의 표준 정규분포로 스케일링했습니다.
- **Selection Reason (왜 StandardScaler인가?)**: 본 프로젝트의 핵심인 **K-Means(거리 기반)**와 **PCA(분산 기반)** 알고리즘은 변수의 절대 수치에 민감합니다. 금액대가 큰 '신선식품(Fresh)'에만 모델이 좌우되지 않도록, 'Detergents_Paper'처럼 금액은 적지만 채널 구분력이 높은 변수의 영향력을 **동일한 가중치로 반영**하기 위해 선택했습니다.

## 3. 머신러닝 프로세스

이 섹션에서는 **(1) PCA**로 차원을 축소한 뒤 **(2) K-Means 클러스터링**으로 고객 페르소나를 도출하고, **(3) 분류 모델**로 채널(호레카 vs 소매)을 예측한 후 **(4) Feature Importance·SHAP**으로 모델의 판단 근거를 해석합니다.

---

### 3.1 PCA

원본 6개 구매액 변수는 서로 상관이 있고 스케일 차이도 있어, 이대로 거리 기반 분석을 하면 일부 변수가 결과를 지배할 수 있습니다. **PCA(주성분 분석)**로 차원을 축소하면 변수 간 상관을 반영한 **소수의 주성분**만으로 데이터를 표현할 수 있고, 이후 K-means나 시각화 해석이 수월해집니다.

**적용 방식**

- **입력**: 전처리(로그 변환 + StandardScaler)된 6개 구매액
- **설정**: `n_components=0.8`(설명 분산 80% 유지) → 주성분 수 [수치: n_components]개, 누적 설명 분산 비율 [수치: explained_variance_ratio]
- **출력**: 각 고객별 **주성분 점수(PC1, PC2, …)** — 군집화·Biplot·산점도에 사용

PCA Biplot에서는 PC1–PC2 평면에 고객 점수와 변수 로딩(화살표)을 함께 그려, 어떤 구매 항목이 어떤 방향(군집·채널)과 연관되는지 해석했습니다.

### 3.2 K-Means 클러스터링 (고객 페르소나 도출)

**PCA로 얻은 주성분 점수(PC 좌표)** 위에서 K-means를 수행해, "구매 패턴이 비슷한 고객"끼리 군집으로 나눴습니다. 원본 6개 변수 공간이 아니라 PCA 공간에서 클러스터링하면 상관·스케일 영향을 줄인 상태에서 군집을 잡을 수 있습니다.

**파이프라인 요약**

1. **전처리**: 6개 구매액 → log1p → StandardScaler
2. **PCA**: 위 3.1과 동일하게 적용 → PC 점수 산출
3. **K-means**: PC1, PC2, …를 입력으로 **5개 군집** 클러스터링. **실루엣 스코어**: [수치: silhouette_score]

**군집별 고객 수**는 대시보드 막대 차트에, **군집별 평균 구매액** 및 **전체 대비 비율**은 **고객 페르소나(Cluster Memo)** 도출에 활용했습니다. 예를 들어 "Fresh·Frozen 비중이 높은 군집", "Grocery·Detergents_Paper 비중이 높은 군집"처럼 군집별 특성을 요약해 페르소나로 정리했습니다.

### 3.3 머신러닝 분류 모델 (Classification)

**타겟**: Channel 1(호레카) → 0, 2(소매) → 1

### 3.4 Feature Importance, SHAP 분석 (모델의 판단 근거)

채널 예측 모델이 **어떤 변수를 근거로 판단하는지**를 보여 주기 위해 **Feature Importance**와 **SHAP**을 사용했습니다.

**Feature Importance (계수 절댓값)**  
Logistic Regression의 계수 절댓값으로 변수 중요도를 보면 **Milk**, **Grocery**가 채널 구분에 가장 큰 영향을 주는 변수로 나타났습니다.

- **SHAP summary plot**: 변수별 SHAP 값 분포와 방향(양/음)을 보여 주어, "Milk가 높을수록 소매 쪽 예측에 기여" 같은 해석이 가능합니다.

## 4. TabPy 연동 및 태블로 대시보드 제작

### TabPy 역할

**TabPy**는 Tableau가 **Python 스크립트를 호출**할 수 있게 해 주는 서버입니다. 이를 통해 대시보드에서 **실시간으로** 군집 ID, PCA 좌표, 채널 예측값·확률을 계산할 수 있습니다.

### 연동 흐름

1. **TabPy 서버** 실행 후, `tabpy_wholesale_cluster.py`를 배포해 다음 함수를 등록합니다.
   - `get_cluster`: 6개 구매액 → **군집 ID** (0~4)
   - `get_pca_coords`, `get_pca1`, `get_pca2`, `get_pca3`: 6개 구매액 → **PCA 좌표** (Biplot·산점도용)
   - `get_channel`: 6개 구매액 + Region → **채널 예측** (0/1), 선택한 모델명(예: LogisticRegression, XGBoost)을 8번째 인자로 전달
   - `get_channel_proba`: 동일 입력 → **채널 1(소매) 확률**
   - `get_feature_importance`: (선택) 특성 중요도

2. **Tableau**에서는 계산 필드에서 `SCRIPT_INT`, `SCRIPT_REAL`로 위 함수를 호출하고, **Select ML Model** 매개변수로 모델 이름을 넘깁니다. 인자 순서(Fresh, Milk, Grocery, Frozen, Detergents_Paper, Delicassen, Region, ModelName)를 스크립트와 맞추는 것이 중요합니다.

3. **모델·스칼라 파일**(wholesale_scaler.pkl, wholesale_cluster_model.pkl, wholesale_logistic.pkl 등)은 TabPy 스크립트와 **같은 폴더**에 두어, 서버가 pkl을 읽을 수 있게 합니다.

자세한 매개변수 설정·계산 필드 예시는 프로젝트 내 `태블로_Select_ML_Model_연동_참고.md`를 참고하면 됩니다.

### 대시보드 구성

대시보드는 크게 다음 블록으로 구성했습니다.

1. **데이터 탐색 및 기초 통계**: 비즈니스 KPI 스코어 카드, 상품별 박스 플롯, 지역·채널 파이 차트
2. **K-means 클러스터링**: 군집별 고객 수 막대 차트, Cluster Memo(군집별 페르소나 요약)
3. **PCA Biplot / 채널 예측**: PCA 산점도(군집·채널 색상), Biplot 변수 화살표, 군집·채널 해석 문구
4. **채널 예측 모델 성능**: 모델 비교표, ROC Curve, Feature Importance, SHAP 시각화, 성능 지표 해석
5. **머신러닝 모델·지표 설명**: 사용한 모델과 지표(Accuracy, AUC, Precision, Recall 등)에 대한 짧은 설명 표

이 구성을 통해 "데이터 이해 → 세분화 → 예측 → 해석"이 한 화면에서 이어지도록 했습니다.

## 5. 결과 해석 및 비즈니스 제언

### 인사이트 요약

- **고객 세분화**: PCA 기반 K-means로 도출한 5개 군집은 "신선식품 위주", "가공식품·세제·종이 위주", "고매출·다품목" 등으로 구분할 수 있으며, 군집별 평균 구매액과 전체 대비 비율로 **타겟 마케팅**이나 **재고·가격 정책**에 활용할 수 있습니다.
- **채널 예측**: **Milk**, **Grocery** 구매가 채널(호레카 vs 소매) 구분에 가장 큰 영향을 주었습니다. 신규 고객의 구매 패턴만으로도 채널을 추정해 **채널별 맞춤 메시지**나 프로모션 설계에 참고할 수 있습니다.
- **대시보드**: TabPy 연동으로 **모델을 바꿔 가며** 예측 결과를 비교할 수 있어, 운영 단계에서도 "지금은 Logistic Regression으로 보고 있고, 필요 시 XGBoost로 전환" 같은 유연한 활용이 가능합니다.

### 한계 및 향후 과제

- 데이터는 **한 시점의 연간 구매액**이므로, 시계열 변화나 코호트 분석은 추가 데이터가 필요합니다.
- 채널 레이블이 이미 존재하는 데이터로 학습했기 때문에, **완전 신규 고객**에 대한 예측은 실제 채널 정보가 쌓이면 재학습·검증하는 것이 좋습니다.
