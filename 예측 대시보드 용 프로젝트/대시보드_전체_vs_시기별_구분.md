# 대시보드: 전체 기간 vs 특정 시기 분석 구분

Olist 데이터를 대시보드할 때 **전체 2016~2018을 한꺼번에 보는 주제**와 **특정 시기(이벤트·시즌)만 골라 보는 주제**를 나누어 구성하는 가이드입니다.

---

## 1. 왜 구분하는가

| 관점 | 전체 기간 분석 | 특정 시기 분석 |
|------|----------------|----------------|
| **목적** | 전체 트렌드, 벤치마크, 유입·매출 흐름 파악 | 블랙프라이데이·시즌 등 **이벤트/시즌성** 영향 분석 |
| **데이터** | 2016~2018 통합 지표, 주/월 시계열 | 이벤트 기간·시즌 구간만 필터링한 지표 |
| **대시보드** | KPI 카드, 전체 시계열, 코호트·세그먼트 요약 | “이벤트 주 vs 평소”, “시즌 구간 비교” 차트 |

- **전체 매출·유입 트렌드** → 전체 기간으로 두고, 기간 필터는 “보는 구간”만 바꿀 때 유리.
- **갑자기 변동이 큰 시기**(블랙프라이데이, 11월, 12월 등)나 **시즌성이 있는 상품** → 해당 기간/카테고리만 잘라서 비교하는 전용 뷰가 유리.

---

## 2. 주제별 적절한 관점 (전체 vs 시기별)

### 2.1 전체 기간이 적절한 주제 (Whole-period)

| 주제 | 노트북 | 이유 | 대시보드 예시 |
|------|--------|------|----------------|
| **전체 매출·주문 트렌드** | 05-C | 장기 추이, 성장 곡선, 예측 베이스라인 | 월/주별 매출·주문 수 라인 차트, 기간 필터만 제공 |
| **유입·검색 트렌드** | 02 Google Trends | Olist 기간(2016~2018)과 맞춘 검색 관심도 | Trends 시계열 + 매출 시계열 같은 화면 |
| **고객 세그먼트·페르소나** | 03-A | “전체 데이터 기준” 한 번의 군집이 해석하기 쉬움 | 세그먼트별 KPI, 연도/분기 필터로 시기별 구성만 확인 |
| **코호트·리텐션·LTV** | 06-D | 코호트별 장기 행동 패턴이 목적 | 코호트 월/주 × 경과 기간 리텐션, 전체 또는 기간 필터 |
| **상품 연관(함께 구매)** | 08-F | 전 기간 누적 시 “안정적인” 연관 패턴 | cat_a × cat_b TOP N, 필요 시 주/기간 필터로 슬라이스 |

→ **대시보드**: “**오버뷰 / 트렌드**” 탭에 두고, **기간 필터(날짜 범위)**만 두어 “전체” 또는 “일부 구간” 선택.

---

### 2.2 특정 시기가 적절한 주제 (Period-specific / 이벤트·시즌)

| 주제 | 노트북 | 이유 | 대시보드 예시 |
|------|--------|------|----------------|
| **이벤트 구간 비교** (블랙프라이데이, 11월 등) | 05-C, 09-G | 특정 주/월만 필터해 “이벤트 주 vs 평소” 매출·결제 구조 비교 | “이벤트 기간” 필터 또는 전용 페이지: 11월 주별 매출, 가격대·결제 수단 비율 |
| **시즌성 있는 카테고리** (선물·계절 상품 등) | 05-C, 04-B, 08-F | 특정 카테고리는 연중 특정 월/분기에 피크 | 카테고리 선택 + 월/분기 시계열, “시즌 구간” 하이라이트 |
| **배송·만족도 이벤트 구간** | 07-E, 04-B | 이벤트 기간 배송 지연·리뷰 이슈 집중 확인 | 주별 배송 소요일·지연 비율·리뷰 점수, 11월·12월 등만 필터 |
| **가격대·결제 수단 이벤트기** | 09-G | 프로모션 기간 할부·보레 등 비율·만족도 | “이벤트 주” vs “비이벤트 주” 가격대·결제 수단별 비교 테이블/바 |

→ **대시보드**: “**시즌 / 이벤트**” 탭을 두고, **사전 정의 기간**(예: Black Friday 주, 12월, 분기) 또는 **사용자 선택 기간** 필터로만 분석.

---

### 2.3 둘 다 쓰는 주제 (전체 + 시기 필터)

| 주제 | 노트북 | 전체 용도 | 시기별 용도 |
|------|--------|-----------|-------------|
| **리뷰 만족도·NPS** | 04-B | 카테고리·가격대별 전체 평균, 벤치마크 | 주/월별로 “언제 만족도가 떨어졌는지” 추적, 이벤트 주 비교 |
| **배송 성능** | 07-E | 전체 평균 배송일·지연 비율 | 이벤트/피크 기간 배송·지연·리뷰만 필터 |
| **가격대·결제 성과** | 09-G | 전체 가격대·결제 수단 구조 | 시즌/이벤트 구간만 잘라 동일 지표 비교 |
| **시계열·예측** | 05-C | 전체 추이 + 예측 | “11월만”, “Q4만” 등 구간 선택 시 계절성 확인 |

→ **대시보드**: 같은 지표를 **기간 필터** 하나로 “전체” vs “특정 시기” 전환. 필요하면 “**이벤트 기간**” 체크 리스트(예: 2017-11-24 주, 2018-11-23 주)를 필터 옵션으로 두기.

---

## 3. 대시보드 구조 제안

```
[ 오버뷰 / 트렌드 ]  ← 전체 매출·유입·시계열, 코호트·세그먼트 요약 (기간 필터만)
       │
       ├─ KPI 카드: 전체(또는 선택 기간) 매출·주문 수·고객 수
       ├─ 시계열: 월/주별 매출·주문 수, Google Trends
       ├─ 코호트·리텐션 요약
       └─ 세그먼트·연관 구매 요약

[ 시즌 / 이벤트 ]   ← 특정 시기만 골라서 보는 전용 뷰
       │
       ├─ 기간 선택: "Black Friday 주", "12월", "Q4" 등 (사전 정의 또는 사용자 선택)
       ├─ 이벤트 vs 비이벤트 비교: 매출·주문 수·가격대·결제 수단
       ├─ 시즌성 카테고리: 카테고리별 월/분기 시계열
       └─ 배송·리뷰: 이벤트 기간 배송 소요일·지연·만족도
```

- **전체 쪽**: “기간 필터 = 보는 구간”만 바꾸고, 지표 정의는 동일.
- **시즌/이벤트 쪽**: “이벤트 기간”을 미리 정의해 두거나, 사용자가 “시작일~종료일”로 지정한 구간만 집계.

---

## 4. 데이터·노트북 쪽에서 할 수 있는 것

- **이미 있음**: 모든 노트북에 **주 단위(`order_week_start` 등)** 가 있으므로, Looker에서 **날짜/주 필터**만 걸면 “전체” vs “특정 주/월” 분석 가능.
- **추가하면 좋은 것** (선택):
  - **이벤트 플래그**: `order_purchase_timestamp` 기준으로 “Black Friday 주(11월 4주 등)”, “12월”, “Q4” 같은 `event_period` 컬럼을 00 전처리 또는 각 노트북에서 추가 → 대시보드에서 “이벤트 기간” 필터로 바로 사용.
  - **시즌성 카테고리 목록**: 시즌성이 큰 카테고리(선물, 특정 계절 상품 등)를 메모해 두고, 05-C·08-F 등에서 해당 카테고리만 필터한 뷰/테이블을 하나 더 내보내기.

원하면 **이벤트 플래그 정의(예: BR 블랙프라이데이 날짜)**와 **00 또는 03~09에 넣을 코드 스니펫**까지 이어서 정리해 줄 수 있습니다.

## 5. 요약 표 (Looker 구성 시 참고)

| 분석 주제 | 기본 뷰 | 전용 “시즌/이벤트” 뷰 |
|-----------|---------|---------------------------|
| 전체 매출·유입 트렌드 | ✅ 전체 + 기간 필터 | — |
| Google Trends | ✅ 전체 기간 | — |
| 고객 세분화·페르소나 | ✅ 전체 기준 세그먼트 | (선택) 연도/분기 필터 |
| 리뷰 만족도·NPS | ✅ 전체 + 기간 필터 | ✅ 이벤트 기간만 필터 |
| 시계열·예측 | ✅ 전체 시계열 | ✅ 11월·12월·Q4 등 구간 비교 |
| 코호트·리텐션 | ✅ 전체 코호트 | (선택) 코호트 월 필터 |
| 배송 성능 | ✅ 전체 + 기간 필터 | ✅ 이벤트 기간 배송·지연 |
| 상품 연관 | ✅ 전체 연관 | ✅ 이벤트/시즌 구간 연관 |
| 가격대·결제 성과 | ✅ 전체 + 기간 필터 | ✅ 이벤트 기간 가격대·결제 비교 |

이 구분을 기준으로 **“오버뷰/트렌드”**와 **“시즌/이벤트”** 두 블록으로 나누면, 전체 흐름과 시기별 이슈를 같이 보기 좋습니다.
