# 연도별 비교를 위한 A–G 파일 정리 & 대비 분석 주제

2016·2017·2018 **연도 기준 비교**가 가능하도록 A–G 노트북을 어떻게 쓰고, **어떤 대비 분석**을 준비할지 정리했습니다.  
K-Means 세그먼트 변수(객단가, 구매 개수, 첫/재구매, 만족도, 할인률 등)의 **데이터 존재 여부**와 **연도별 적용 방법**을 포함합니다.

---

## 1. 데이터 한계 (연도·변수)

### 1.1 연도별 커버리지 (재확인)

| 연도 | 주문 수 | 월 커버리지 | 연도별 비교 시 유의점 |
|------|---------|-------------|------------------------|
| 2016 | 267건 | 9월 1, **10월 265**, 12월 1 | **실질 10월만** 의미 있음. 연도 단위 K-Means는 비추천. |
| 2017 | 43,428건 | **1~12월 전부** | 연도별 비교의 **기준 연도**. 2017 단독·2017 vs 2018 가능. |
| 2018 | 52,783건 | **1~8월만** | **9~12월 없음**. 2017 vs 2018는 **1~8월 동기간**으로 비교. |

→ **연도별 K-Means·세그먼트 비교**는 **2017 전체** vs **2018 1–8월**를 “해당 기간 내 고객”으로 나누어 비교하거나, **동기간(1–8월)**만 쓰는 편이 안전합니다. 2016은 10월만 있으므로 “2016년 10월 vs 2017년 10월” 같은 **월 단위** 보조 비교로 두는 것을 권장합니다.

### 1.2 세그먼트 변수별 데이터 존재 여부

말씀하신 변수 중 **Olist에서 바로 쓸 수 있는 것**과 **없거나 대체해야 하는 것**을 구분했습니다.

| 변수 | 데이터 존재 | 출처·비고 |
|------|-------------|-----------|
| **구매 객단가** | ✅ | `order_payments` 합 → 주문당 결제액. 연도별 주문만 필터해 고객별 평균 또는 총액/주문수 |
| **구매 개수** | ✅ | `order_items` 행 수 또는 주문별 item 수 합계 → 고객별 “구매 상품 수” |
| **구매 횟수** | ✅ | `orders` 기준 고객별 `order_id` 개수 |
| **제품 구매 카테고리** | ✅ | `order_items` + `products.product_category_name` → 고객별 최다 구매 카테고리 또는 카테고리 수 |
| **첫 구매 여부** | ✅ | 고객별 최초 주문일 = 해당 연도(또는 기간) 내 첫 주문인지 여부 |
| **재구매 여부** | ✅ | 해당 기간 내 주문 횟수 ≥ 2 |
| **재구매 횟수** | ✅ | 해당 기간 내 (주문 횟수 - 1) 또는 재구매한 주문 수 |
| **배송 만족도** | ⚠️ 간접 | **배송 지표**는 07-E: 배송 소요일·지연 여부. “만족도”는 **리뷰 점수**와 연계해 해석 (배송 빠르면 리뷰 높은지 등). |
| **구매 만족도** | ✅ | `order_reviews.review_score` (04-B). 주문·고객과 조인 후 고객별 평균 리뷰 점수 |
| **할인률** | ❌ | **할인/쿠폰 컬럼 없음.** 대체: (1) `payment_type == 'voucher'` 비율, (2) 주문 시점·카테고리별 **평균 단가 비교**(이벤트 vs 비이벤트)로 “할인 효과 추정”만 가능. |

→ **K-Means 군집용 피처**로는 **객단가, 구매 개수, 구매 횟수, 카테고리(수/대표), 첫·재구매 여부, 재구매 횟수, 구매 만족도(리뷰)**까지 사용하고, **할인률**은 제외하거나 **voucher 비율**을 “프로모션 사용 성향” 대리 변수로 넣는 방식을 권장합니다.

## 2. A–G 파일을 연도별 비교용으로 정리

각 파일이 **연도 필터**만 추가하면 “연도별로 같은 분석”을 할 수 있도록 정리했습니다.  
(2016은 10월만 있으므로 03-A·세그먼트는 2017·2018 위주로 적용하는 것을 권장.)

| 파일 | 주제 | 연도별 비교 시 할 일 | 산출물(연도별) |
|------|------|---------------------|----------------|
| **03-A** | 고객 세분화·K-Means 페르소나 | 연도(또는 1–8월)별로 **동일 피처**로 군집 후, **세그먼트 비율·평균 지표** 비교 | 연도별 세그먼트 구성 %, 세그먼트별 객단가·구매횟수·만족도 |
| **04-B** | 리뷰 만족도·NPS 스타일 | 연도(또는 월) 필터 추가 → **카테고리별·가격대별 만족도** 연도별 비교 | 연도별 평균 리뷰 점수, 저평점 비율, 카테고리별 추이 |
| **05-C** | 시계열·예측 | **연도별 시계열** 분리 또는 **2017 vs 2018** 월별 매출·주문 수 비교 | 연도별 월별 매출·주문, 성장률, (선택) 다음 기간 예측 |
| **06-D** | 코호트·LTV·리텐션 | **첫 구매 연도(코호트)** 기준으로 리텐션·ARPU 비교 (2016 코호트, 2017 코호트, 2018 코호트) | 연도(코호트)별 N개월 리텐션, ARPU |
| **07-E** | 배송 성능·만족도 연계 | 연도(또는 1–8월) 필터 → **배송 소요일·지연 비율** 연도별 비교, 리뷰와 상관 | 연도별 평균 배송일, 지연률, 배송–리뷰 관계 |
| **08-F** | 상품 연관·추천 | 연도(또는 1–8월) 필터 → **같이 구매된 카테고리/상품 쌍** 연도별 비교 | 연도별 TOP 연관 쌍, 트렌드 변화 |
| **09-G** | 가격대·결제 성과 | 연도(또는 1–8월) 필터 → **가격대·결제 수단별** 주문 수·매출·만족도 연도별 비교 | 연도별 가격대·결제수단 구성, voucher 비율 등 |

공통 적용 방법:  
- **연도 컬럼** 추가: `order_purchase_timestamp` (또는 해당 시점)에서 `year` 추출.  
- **비교 기간 통일**: 2017 vs 2018일 때는 **2017년 1–8월 vs 2018년 1–8월**로 제한하면 해석이 깔끔합니다.  
- 03-A만 “2017 전체” vs “2018 1–8월”처럼 **기간 길이**가 다를 수 있으므로, “동일 기간(1–8월)”으로 맞추는 옵션을 두는 것을 권장합니다.

## 3. 연도별 K-Means 세그먼트 — 변수·대비 분석 주제

### 3.1 연도별로 쓸 피처 (권장)

아래는 **연도(또는 1–8월) 단위로 고객을 자르고**, 그 기간 내에서만 집계한 뒤 K-Means에 넣는 구성을 가정합니다.

| 피처 | 설명 | 비고 |
|------|------|------|
| 구매 횟수 | 해당 기간 주문 수 | log1p 권장 |
| 구매 개수 | 해당 기간 총 주문 아이템 수(또는 주문 수) | 03-A의 `order_count`와 동일 개념 |
| 객단가(평균 결제액) | 해당 기간 총 결제액 / 주문 수 | `total_value`/`order_count` 등 |
| 재구매 횟수 | max(0, 주문 수 - 1) 또는 동일 정의 | 첫 구매 여부 = (주문 수 == 1) |
| 구매 만족도 | 해당 기간 주문에 대한 **평균 리뷰 점수** | 04-B 리뷰와 조인 |
| (선택) voucher 비율 | 해당 기간 주문 중 `payment_type == 'voucher'` 비율 | 할인 대신 “프로모션 사용 성향” |
| (선택) 구매 카테고리 수 | 해당 기간 구매한 서로 다른 `product_category_name` 수 | 다양성 지표 |

**첫 구매 여부·재구매 여부**는 **레이블/해석용**으로 두고, 군집 후 “세그먼트별 신규 비율·재구매 비율”을 보는 방식으로 쓰는 것을 권장합니다. (이진 변수만으로 군집하면 구조가 단순해질 수 있음.)

### 3.2 연도별 세그먼트 비교로 다룰 “대비 분석” 주제

- **세그먼트 구성 변화**  
  - 2017(또는 2017 1–8월) vs 2018(1–8월) **세그먼트 비율**이 어떻게 바뀌었는지.  
  - 예: “고객단가·구매횟수 높은 세그먼트 비중이 2018에 증가했다” → 소비 고급화·충성 고객 증가 등.

- **세그먼트별 지표 추이**  
  - 같은 “유형”(예: S0, S1, …)이라도 **연도마다 정의가 달라질 수 있음**을 전제로,  
  - **각 연도 내**에서 세그먼트별 **객단가, 구매 횟수, 만족도, 재구매 비율**을 비교.  
  - “2017의 S0 vs 2018의 S0”보다는 “2017에서 가장 큰 세그먼트 vs 2018에서 가장 큰 세그먼트”처럼 **규모·역할** 기준 비교를 권장.

- **소비자 트렌드 요약**  
  - 연도별 **평균 객단가, 평균 구매 횟수, 평균 만족도, 재구매 비율**을 먼저 보고,  
  - 그 위에 **세그먼트 비율 변화**를 겹쳐서 “고가·다구매 세그먼트가 늘었다/줄었다” 등 **트렌드 문장**으로 정리.

## 5. 구현 순서 제안 (연도별 비교용)

1. **공통**: 00 전처리 후, 모든 주문·결제·리뷰·배송에 **연도**와 **(필요 시) 1–8월 플래그** 추가.  
2. **05-C, 09-G**: 2017 1–8월 vs 2018 1–8월 **매출·주문·객단가·가격대·결제수단** 비교 표·차트.  
3. **03-A**: 2017 1–8월 데이터만으로 고객 집계 → 피처(객단가, 구매 횟수·개수, 만족도, 재구매 등) → K-Means → 세그먼트 라벨 부여. 동일 로직을 **2018 1–8월**에 반복. → 세그먼트 비율·세그먼트별 평균 지표 비교.  
4. **04-B, 07-E**: 연도(1–8월) 필터로 만족도·배송 지표 연도별 비교.  
5. **06-D**: 코호트 = 첫 구매 연도(또는 첫 구매 1–8월)로 2017 vs 2018 유입 코호트 리텐션 비교.  
6. **08-F**: 2017 1–8월 vs 2018 1–8월 **연관 쌍** 비교.  
7. **종합**: “2017 대비 2018 무엇이 바뀌었나” 요약 + “2018 하반기 대비” 체크리스트 (2017 하반기·BF 참고).

이 순서대로 하면 **A–G를 연도 기준으로 재사용**하면서, **세그먼트 변화·소비자 트렌드·대비 전략**까지 한 번에 정리할 수 있습니다.  
필요하면 “연도별 비교 전용” 노트북 하나를 두고, 위 표의 주제별로 섹션을 나누어 A–G 코드를 **연도 필터만 넣어** 재사용하는 구조를 추천합니다.
