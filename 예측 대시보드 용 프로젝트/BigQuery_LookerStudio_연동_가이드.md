# Olist 분석 1~9 → BigQuery 연동 & Looker Studio 시각화 가이드

나중에 **BigQuery에 데이터를 올리고 Looker Studio로 시각화**할 때 참고할 수 있도록,  
주제별로 **어떤 테이블을 BQ에 두고, Looker에서는 어떻게 그리면 좋을지** 요약해 두었습니다.  
구체적인 쿼리·연동 단계는 필요할 때 단계별로 정리해 드릴 수 있습니다.

- **전체 기간 vs 특정 시기(이벤트·시즌) 구분**: → **[대시보드_전체_vs_시기별_구분.md](./대시보드_전체_vs_시기별_구분.md)** 참고.  
  전체 매출·유입 트렌드는 “전체 + 기간 필터”, 블랙프라이데이·시즌성 상품 등은 “시즌/이벤트” 전용 탭으로 나누는 구성을 권장.

## 전체 흐름 (한 줄)

**Python(노트북) → CSV/Parquet 내보내기 → BigQuery 테이블 로드 → Looker Studio에서 BQ 데이터 소스 연결 → 차트/필터 구성**

---

## 시각화하기 좋은 주제 vs 상대적으로 어려운 주제

| 구분 | 주제 | 이유 |
|------|------|------|
| **시각화 추천** | **B 리뷰 만족도**, **C 시계열·예측**, **E 배송 성능**, **F 상품 연관**, **G 가격대·결제** | 라인·막대·스코어카드·테이블만으로 스토리가 명확. 차트 타입이 단순하고 Looker 기본 차트로 바로 구현 가능. |
| **보통** | **D 코호트·리텐션** | 리텐션 행렬은 히트맵이 직관적인데, Looker 기본에 히트맵이 없어 피벗 테이블+조건부 서식으로 대체. |
| **상대적으로 어려움** | **A 고객 세분화·페르소나** | 세그먼트 하나가 “주문수·결제액·카테고리·결제수단·지역” 등 여러 차원을 동시에 가짐. “한 장의 페르소나”로 요약하려면 레이더/다차원 차트가 좋은데, Looker에서 한눈에 보기엔 필터+테이블+막대 여러 개를 조합해야 함. |

**대시보드 구성을 먼저 하고 싶다면** B, C, E, F, G부터 올리고, A·D는 “요약 테이블 + 필터” 위주로 단순화해 넣는 걸 권장.

## 전체 vs 시기별: 대시보드 탭 구분 (요약)

| 관점 | 적합한 주제 | Looker 구성 |
|------|-------------|-------------|
| **전체 기간** | 전체 매출·유입 트렌드(02, 05-C), 세그먼트(03-A), 코호트(06-D), 연관 구매(08-F) | “오버뷰/트렌드” 탭, **기간 필터**만 제공 |
| **특정 시기** | 이벤트(블랙프라이데이 등)·시즌 구간 매출·가격대·결제(05-C, 09-G), 배송·리뷰(07-E, 04-B) | “시즌/이벤트” 탭, **이벤트 기간** 또는 사용자 선택 기간 필터 |
| **둘 다** | 리뷰(04-B), 배송(07-E), 가격대·결제(09-G), 시계열(05-C) | 같은 지표를 기간 필터로 “전체” vs “이벤트 구간” 전환 |

## 주제별 BigQuery 테이블 & Looker 시각화 제안

### 00. 데이터 마트 (전처리 결과)

| BQ 테이블 | 용도 | Looker 활용 |
|-----------|------|-------------|
| `olist_customers`, `olist_orders_delivered`, `olist_order_items`, `olist_products`, `olist_order_payments`, `olist_order_reviews` 등 | 원천·집계용 마트 | 다른 분석 페이지에서 필터/드릴다운용 차원 테이블로 연결 |

- **시각화**: 단독 페이지보다는, **필터(기간·지역·카테고리)** 공통 데이터 소스로 사용.

### 02. Google Trends (BR 2016–2018)

| BQ 테이블 | 컬럼 예시 | Looker 활용 |
|-----------|-----------|-------------|
| `google_trends_br` | `date`, `keyword`, `interest` | **시계열 라인 차트**: 날짜 × interest, 차원에 keyword. 03-C(매출 시계열)와 같은 페이지에 배치해 “실제 매출 vs 검색 관심” 비교. |

- **시각화**:  
  - 시계열 라인(키워드별 라인 또는 필터).  
  - Olist 월별 매출과 **같은 기간**으로 맞춰 한 화면에 두기.

---

### 03-A. 고객 세분화 & 페르소나

| BQ 테이블 | 컬럼 예시 | Looker 활용 |
|-----------|-----------|-------------|
| `customer_segments` | `customer_unique_id`, `segment`, `order_count`, `total_value`, `avg_order_value`, `top_category`, `main_payment_type`, `customer_state` | **페이지 2**: 세그먼트별 KPI 카드(고객 수, 평균 주문 수, 평균 결제액). **테이블/바 차트**: 세그먼트 × 지표. **필터**: segment, customer_state, top_category. |

- **시각화**:  
  - 세그먼트 선택 필터 → 해당 세그먼트의 지표만 표시.  
  - “프로모션 타겟 후보”용으로 segment + state 조합 테이블.

### 04-B. 리뷰 만족도·NPS

| BQ 테이블 | 컬럼 예시 | Looker 활용 |
|-----------|-----------|-------------|
| `review_by_category` | `product_category_name`, `리뷰수`, `평균_점수`, `저평점_비율`, `고평점_비율` | **바 차트**: 카테고리별 평균 점수·저평점 비율. **필터**: 카테고리. |
| `review_by_price_bin` | `price_bin`, `리뷰수`, `평균_점수`, `저평점_비율` | 가격대별 만족도 바/라인. |

- **시각화**:  
  - “만족도 개선 우선순위” 대시보드: 카테고리·가격대별 정렬 테이블 + 바 차트.  
  - NPS 스타일 점수는 **스코어카드** 1개.

### 05-C. 시계열·예측

| BQ 테이블 | 컬럼 예시 | Looker 활용 |
|-----------|-----------|-------------|
| `monthly_revenue` | `month`, `revenue`, `order_count` | **시계열 라인**: month × revenue, order_count. |
| `monthly_revenue_by_category` | `month`, `product_category_name`, `revenue` | **라인 차트**: 카테고리별 선택 필터 또는 여러 라인. |
| `revenue_forecast` (Prophet 등 결과) | `ds`, `yhat`, `yhat_lower`, `yhat_upper` | **라인**: 실제 + 예측 구간. |

- **시각화**:  
  - 페이지 3: **실제 매출/주문 수** 시계열 + **Google Trends** 시계열(02).  
  - “다음 달 집중 카테고리” KPI 카드(예측 또는 성장률 기준).

### 06-D. 코호트·LTV·리텐션

| BQ 테이블 | 컬럼 예시 | Looker 활용 |
|-----------|-----------|-------------|
| `cohort_retention` | `cohort_month`, `month_num`, `retention_pct`, `n` | **히트맵**: cohort_month × month_num, 색상 = retention_pct. |
| `cohort_ltv` | `cohort_month`, `고객수`, `평균_주문수`, `평균_LTV` | **테이블** + **바 차트**: 코호트별 LTV. |

- **시각화**:  
  - **리텐션 히트맵** (Looker에서 pivot 테이블 + 조건부 서식 또는 커스텀 차트).  
  - 코호트별 리텐션 곡선(라인): 경과월 × retention_pct, 차원 cohort_month.

## BigQuery 올리는 방법 (요약)

1. **Python에서 내보내기**  
   - 각 노트북 마지막에 `df.to_csv(...)` 또는 `df.to_parquet(...)` 로 저장 (이미 일부 적용됨).  
   - 또는 `pandas_gbq.to_gbq(df, "dataset.table")` 로 직접 BQ에 적재.

2. **BQ에서**  
   - 데이터셋 생성 후, CSV/Parquet 업로드 또는 `bq load`, `INSERT` 등으로 테이블 생성.  
   - 뷰/스테이징 테이블로 나눌지는 데이터 크기·갱신 주기에 따라 결정.

3. **Looker Studio**  
   - “데이터 추가” → “BigQuery” 커넥터 선택 → 위 테이블(뷰) 연결.  
   - 페이지/차트별로 필요한 테이블만 연결하거나, 하나의 “마스터” 데이터 소스에 여러 테이블 조인해 사용.

## 나중에 물어보시면 좋은 것들

- **특정 주제만** BQ 테이블 설계(컬럼·파티션)·로드 순서  
- **Looker에서** 히트맵/리텐션 곡선 만드는 방법  
- **갱신 주기** (일/주/월)에 맞춘 BQ 스케줄 쿼리 + Looker 캐시 설정  
- **비용** 줄이기 (저장 쿼리, 파티션, Looker 캐시)

원하실 때 “03-A만 BQ 올리는 법”, “Looker에서 코호트 히트맵 그리는 법”처럼 **주제 번호나 이름을 적어 주시면** 그에 맞춰 단계별로 정리해 드리겠습니다.
